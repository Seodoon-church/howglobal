## 0. Claude Code 실행 방법

저장소 루트에서 Claude Code를 실행하고 아래 프롬프트를 붙여 넣는다.

```
docs/ESCO_개발기획서.md 를 읽고 구현해줘.
CLAUDE.md의 작업 방식(계획 → 방향 점검 → 컨펌 → 실행 → 개발일지)을 지키고,
Phase별로 끝날 때마다 무엇을 바꿨는지 보고하고 다음 Phase 진행 여부를 물어봐줘.
```

- 이 문서 자체가 1차 컨펌된 계획이다. Claude Code는 **Phase 시작 전에 수정할 파일 목록만 다시 보여주고** 진행한다.
- 공개 페이지는 `tools/build.py`에서 생성한다. `public/*.html`(admin.html 제외)과 `public/assets/i18n.js`는 **직접 편집 금지**.

## 1. 배경과 목표

### 배경
- 하우인터내셔널은 켑코이에스㈜(에너지효율화사업자)·㈜투반산업(EPC, 3세대 스마트 AI LED 제조·시공)과 함께 **조명 ESCO 사업 영업**을 시작했다. 하우인터내셔널의 역할은 **제안·사업 총괄**(상담 창구, 무료 진단 연결, 계약~준공 관리).
- 대상별 제안서 11종(PDF)은 이미 만들어져 있고, 영업 1순위는 **아파트**다.
- 홈페이지(howglobal.co.kr)에 ESCO 소개와 **무료 진단 신청 접수** 창구가 필요하다.

### 목표
1. ESCO 사업을 설명하는 독립 페이지 `esco.html` (국/영, SEO 포함)
2. 페이지 안에서 **무료 절감 진단 신청**을 받고, Firestore `inquiries`에 `type: "esco"`로 저장
3. 관리자 페이지에서 ESCO 신청을 **따로 모아 보고**, 시설 정보까지 확인
4. 사이트 전체에서 ESCO로 들어오는 동선(메뉴, 홈, 사업분야, 견적 폼) 연결

### 하지 않는 것 (범위 밖)
- 제안서 PDF 공개 다운로드 (추정 단가가 들어 있어 **비공개**, 신청자에게 개별 발송)
- 신청 즉시 이메일/카카오 알림 (Cloud Functions·유료 요금제 필요 → 추후 별도 과제)
- 고지서 파일 업로드 (Storage 규칙 변경 필요 → 추후 과제)
- `firestore.rules` 변경 (기존 `inquiries` 규칙을 그대로 쓴다)

## 3. 수정 파일과 작업 단계

### Phase 1 — 페이지 생성 (`tools/build.py`)

1. `PAGES`에 `"esco":"esco.html"` 추가
2. `header()`의 메뉴에 `nav("nav.esco","esco")` 추가 (위치: 사업분야 다음)
3. `footer()` 사이트맵 링크에 ESCO 추가
4. `T`에 ESCO용 키 추가 (모든 키는 `(한국어, 영어)` 튜플 — 영어는 Claude Code가 자연스럽게 번역)
   - 키 접두어: `nav.esco`, `esco.*`, `ov.d4.*`(홈 사업부 카드), `biz.d4.*`(사업분야 섹션), `qt.type.esco`(견적 폼)
5. `def esco():` 함수 추가 → 아래 **4장 페이지 구성**대로 섹션 작성
   - `head()` 호출 시 title/description/keywords와 `extra_ld`에 `Service` + `FAQPage` JSON-LD 포함
   - `breadcrumb_ld()` 사용 (HOME / ESCO)
6. `main()`의 `files`에 `"esco.html":esco()` 추가
7. `seo_and_config()`의 `pages`·`freq`·`pri`에 `esco.html` 추가 (monthly / 0.9)
8. 홈 `home()`: 사업부 개요에 **DIV. 04 에너지(ESCO)** 카드 추가 → `esco.html` 링크
   - 기존 3개 카드 레이아웃이 4개에서 깨지지 않는지 확인 (필요 시 styles.css 그리드 조정)
9. 사업분야 `business()`: **DIV. 04 · 에너지사업부** 섹션 추가 (요약 + "ESCO 자세히 보기 →" + "무료 진단 신청 →")
10. 견적 `quote()`: 문의 유형 카드에 `esco`(ESCO 진단) 추가. 선택하면 안내 문구와 함께 `esco.html#apply`로 이동하는 링크 표시 (견적 폼에서 직접 제출해도 `type:"esco"`로 저장되게)
11. 상단 띠(topstrip)·브랜드 라벨·Organization JSON-LD의 `description`에 "에너지(ESCO)"를 넣을지는 **Claude Code가 제안만 하고 사용자 확인 후** 반영 (사이트 정체성 문구라서)

### Phase 2 — 동작 (`public/assets/app.js`)

1. `initEscoForm()` — `#esco-form` 제출 처리
   - 필드 수집 → 필수값 검증 → `message` 자동 생성(5장 참고) → `window.HOW_submitInquiry(data)`
   - Firebase 미설정·저장 실패 시 기존 `mailFallback` 패턴으로 mailto 폴백
   - 완료 시 폼 숨기고 완료 박스 표시
2. `initEscoCalc()` — 간이 절감 계산기 (6장 참고)
   - 계산기 결과를 신청 폼에 이어받기: "이 조건으로 진단 신청" 버튼 → 시설 유형·월 전기요금을 폼에 채우고 `#apply`로 스크롤
3. 대상 카드 클릭 시 상세(강점·예상 절감률) 펼침 — `<details>` 요소로 구현하면 JS 불필요(권장)
4. `?type=` 파라미터 처리 패턴은 견적 폼과 동일하게: `esco.html?facility=apartment` → 폼의 시설 유형 미리 선택
5. 기존 init 호출부에 두 함수 등록. `localStorage`는 쓰지 않는다.

### Phase 3 — 스타일 (`public/assets/styles.css`)

- 새 클래스는 `.esco-` 접두어로만 추가 (기존 클래스 수정 최소화)
- 필요 컴포넌트: 핵심 수치 3칸(`.esco-kpis`), 4단계 흐름(`.esco-flow`), 비교표(기존 테이블 스타일 재사용), 대상 카드 그리드(`.esco-targets`, 데스크톱 4열·태블릿 2열·모바일 1열), 계산기 박스(`.esco-calc`), 결과 강조(블루워시 배경)
- 접근성: 포커스 표시 유지, 모바일 360px 폭에서 깨지지 않을 것, `prefers-reduced-motion` 준수

### Phase 4 — 관리자 (`public/admin.html`, 소스 파일)

1. 유형 라벨 맵으로 교체:
   `{software:'개발 의뢰', media:'미디어 개발·견적', distribution:'유통 제휴', healthcare:'헬스케어 제휴', other:'기타', esco:'ESCO 진단'}`
   (현재 코드는 `software`가 아니면 전부 "유통 제휴"로 표시하는 버그가 있음 — 같이 수정)
2. 문의함 상단에 필터 버튼: `전체 / ESCO / 그 외`
   - 클라이언트 필터로 구현(이미 받아온 최근 50건에서 거름). 복합 색인 추가 불필요
   - ESCO 건수 배지 표시
3. `type==='esco'` 카드에는 추가 필드 표시: 시설 유형, 시설명, 지역, 규모, 월 전기요금, 연락 가능 시간, 계산기 추정치(있으면)
4. 연락처(`phone`)를 `tel:` 링크로

### Phase 5 — 문서·빌드·검증

1. `npm run build` → 생성물 갱신, 에러 없는지 확인
2. 7장 **검증 체크리스트** 수행
3. `CLAUDE.md` 갱신: 사업 구성에 DIV. 04 추가, Firestore 데이터 모델의 `inquiries.type`에 `esco`와 추가 필드 명시
4. `docs/개발일지.md`에 작업 기록 추가 (무엇·왜·어떻게·배포·잔여)
5. 커밋(한국어 메시지) — **배포는 사용자 확인 후** `npm run deploy:hosting` (규칙 변경 없으므로 rules 배포 불필요)

## 4. 페이지 구성 (`esco.html`) — 섹션별 문구 초안

> 문구는 초안이다. Claude Code는 톤만 다듬고 **숫자·사실은 바꾸지 말 것.**

### 4-1. 히어로 (`subhero` 대신 전용 히어로 권장)
- 브레드크럼: HOME / ESCO
- 아이브로: `DIV. 04 · 에너지사업부 · ESCO`
- H1: **초기비용 0원, 아낀 전기요금으로 갚는 조명 교체**
- 리드: 노후 조명을 3세대 스마트 AI LED로 바꾸고, 공사비는 매달 줄어든 전기요금 안에서만 나누어 갚습니다. 계약이 끝나면 절감액은 전부 고객의 몫입니다.
- 핵심 수치 3칸: `0원` 초기 투자비 · `최대 70%대` 조명 전력 절감(실측 사례 기준) · `5년` 무상 A/S
- 버튼: `무료 절감 진단 신청 →`(#apply) · `예상 절감액 계산하기`(#calc)

### 4-2. ESCO란?
- 설명: ESCO(Energy Service Company)는 에너지 사용자가 자금·기술 부담 없이 고효율 설비로 바꿀 수 있도록, 전문 기업이 먼저 투자하고 절감액으로 돌려받는 에너지이용합리화법 기반 사업 방식입니다.
- 4단계 흐름: ① 무료 진단(고지서·등기구 조사) → ② 선투자·시공(사업자가 전액 부담) → ③ 절감액 상환(줄어든 요금 범위 안에서) → ④ 계약 종료(설비는 고객 소유, 절감액 100% 고객 몫)
- 비교표 (자체 예산 교체 vs ESCO): 초기 비용(수억 원 vs 0원) / 재정 영향(일시 지출 vs 절감액 내 분할 상환) / 유지보수(자체 부담 vs 5년 무상 A/S) / 성과 책임(사용자 부담 vs 사업자 성과 보증)

### 4-3. 3세대 스마트 AI LED
- 비교표:

| 구분 | 1세대 형광등 | 2세대 일체형 LED | 3세대 스마트 AI LED |
|---|---|---|---|
| 1W당 밝기 | 60 lm | 110 lm | 160 lm 이상 |
| 수명 | 3,000시간 | 20,000시간 | 100,000시간 |
| A/S | 없음 | 1년 전후 | 기본 5년 (최대 10년) |
| 고장 시 | 전체 교체 | 전체 교체 | 고장 부품만 교체 |

- 기능 3개: 모듈형 구조 / 모션 감지 디밍(사람·차량 없으면 최저 밝기, 감지 즉시 최대) / 채광 연동 조도 제어
- 주의: "국내 유일" 같은 근거 없는 최상급 표현 금지. 밝기는 **160 lm**으로 통일(165 표기 사용 금지)

### 4-7. 사업 구조
- 3자 카드: 에너지사용자(고객: 의사결정·계약·절감액 내 상환) / 에너지효율화사업자(켑코이에스㈜: 사업 주관·금융·절감량 확인·성과 보증) / EPC(㈜투반산업: 제조·시공·하자보증 60개월·A/S)
- 하단 강조 카드: **하우인터내셔널 — 제안·사업 총괄**(상담 창구, 무료 진단 연결, 의사결정 기구 설명 지원, 계약~준공 관리)
- 진행 절차 7단계(간단 목록): 상담·자료 접수 → 현장 조사·진단 보고서 → 내부 의결(입대의·당회·운영위 등) → 3자 계약 → 시공 → 준공 실사·절감량 확인 → 상환·사후관리

### 4-8. 자주 묻는 질문 (FAQPage JSON-LD로도 출력)
1. 정말 초기 비용이 없나요? → 공사비는 사업자가 먼저 부담하고, 줄어든 전기요금 범위 안에서만 상환합니다.
2. 절감이 예상보다 적으면요? → 준공 후 실사로 절감량을 확인하며, 에너지 효율 보증서에 따라 성과 미달 책임은 사업자가 집니다.
3. 센서등이라 어둡지 않나요? → 사람·차량이 없을 때만 최저 밝기로 낮추고 감지 즉시 최대 밝기로 켜집니다. 실측 사례에서 평균 밝기는 오히려 높아졌습니다.
4. 계약 기간 중 고장 나면요? → 5년 무상 A/S, 고장 부품만 교체합니다.
5. 계약이 끝나면 설비는 누구 것인가요? → 고객 소유가 되고, 이후 절감액은 전부 고객 몫입니다.
6. 진단에 비용이 드나요? → 무료이며 계약 의무가 없습니다.
7. 어떤 자료가 필요한가요? → 최근 1년분 전기요금 고지서(또는 한전 파워플래너 ID), 사업자(고유번호)등록증. 등기구 현황은 현장 조사로 파악합니다.

## 5. 신청 폼 명세

### 필드
| name | 라벨 | 입력 | 필수 | 비고 |
|---|---|---|---|---|
| facility | 시설 유형 | select (4-4의 11개 + 기타 `other`) | ✅ | 값은 영문 key |
| facility_name | 시설명 | text | ✅ | 예: ○○아파트, ○○교회 |
| region | 지역 | text | ✅ | 예: 대전 서구 |
| scale | 규모 | text | | 예: 1,500세대 / 연면적 5,000㎡ / 등기구 약 800개 (아는 만큼) |
| monthly_bill | 월평균 전기요금 | select | | 모름 / 100만원 미만 / 100~300만원 / 300~1,000만원 / 1,000만원 이상 |
| role | 신청인 구분 | select | | 관리사무소 / 입주자대표회의 / 시설·행정 담당 / 대표·임원 / 기타 |
| name | 담당자명 | text | ✅ | |
| phone | 연락처 | tel | ✅ | 숫자·하이픈 9~13자 검증 |
| email | 이메일 | email | ✅ | **규칙상 필수** (`firestore.rules`가 email 문자열 요구) |
| contact_time | 연락 가능 시간 | select | | 오전 / 오후 / 언제든 |
| note | 추가 요청사항 | textarea | | 2,000자 제한 |
| consent | 개인정보 수집·이용 동의 | checkbox | ✅ | 문구: 진단 상담 목적으로만 사용하며 상담 종료 후 파기합니다. |

- 허니팟(스팸 방지): 화면에 보이지 않는 `website` 필드. 값이 있으면 조용히 성공 처리만 하고 저장하지 않음

### 저장 데이터 (`inquiries` 문서)
```js
{
  type: "esco",
  facility, facility_name, region, scale, monthly_bill, role,
  name, company: facility_name,   // 기존 어드민 카드 호환용
  phone, email, contact_time, note,
  calc: { monthly_bill_input, est_low, est_high } | null,  // 계산기 사용 시
  message,        // 자동 생성 — 규칙상 필수(string, 5,000자 미만)
  consent: true,
  lang, page: "/esco",
  createdAt       // firebase.js가 serverTimestamp로 덮어씀
}
```

### message 자동 생성 형식
```
[ESCO 무료 진단 신청]
시설: {시설유형 라벨} / {facility_name} ({region})
규모: {scale||-} · 월 전기요금: {monthly_bill 라벨||-}
신청인: {name} ({role 라벨||-}) · {phone} · 연락 가능: {contact_time||-}
계산기 추정: 월 {est_low}~{est_high}만원 절감 (있을 때만)
요청사항: {note||-}
```
- 생성 후 4,900자에서 자르기(규칙 한도 5,000자 대비 여유)

### 완료 화면
- 제목: 진단 신청이 접수되었습니다.
- 본문: 담당자가 1~2영업일 안에 {phone}으로 연락드립니다. 시설 유형에 맞는 제안서도 함께 보내드립니다. 빠른 진행을 원하시면 최근 1년분 전기요금 고지서를 준비해 주세요.

## 6. 간이 절감 계산기 로직

### 입력
- 시설 유형(11개)
- 월평균 **전체** 전기요금(원, 숫자 입력 — 쉼표 자동)

### 계산
```
조명요금 = 월 전기요금 × 조명비중[유형]
절감 하한 = 조명요금 × (절감률[유형] − 0.10)
절감 상한 = 조명요금 × 절감률[유형]
→ 만원 단위 반올림, "월 약 X~Y만원 · 연 약 X×12~Y×12만원"
```

### 계수 (JS 상수 한 곳에 모아 둘 것 — 추후 투반 실측값으로 교체)

| 유형 | 조명비중(가정) | 절감률 |
|---|---|---|
| apartment (공용 전기 기준) | 0.45 | 0.70 |
| parking | 0.85 | 0.75 |
| factory | 0.15 | 0.65 |
| hospital | 0.25 | 0.50 |
| building | 0.30 | 0.60 |
| retail | 0.30 | 0.60 |
| public | 0.30 | 0.60 |
| university | 0.30 | 0.55 |
| school | 0.35 | 0.65 |
| church | 0.40 | 0.55 |
| welfare | 0.35 | 0.45 |

- 절감률은 대상별 제안서 추정치, **조명비중은 업계 일반값을 가정한 값**이다. 코드 주석에 "가정값 — 실측 데이터 확보 시 교체"라고 명시
- 결과 아래 고정 문구: *이 결과는 업종 평균을 가정한 대략적인 범위입니다. 실제 절감액은 고지서와 현장 조사를 바탕으로 한 무료 진단 후 확정됩니다.*
- 입력값이 비었거나 0 이하이면 결과 숨김. 10억 원 초과 입력은 상한 처리
- 아파트 선택 시 입력 라벨을 "월평균 **공용** 전기요금"으로 바꿔 표시
